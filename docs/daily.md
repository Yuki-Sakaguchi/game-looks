# 毎日ひとつのテーマ（日替わりの手順）

毎晩（日本時間の夜中）、スケジュールタスクで新しいセッションが立ち上がり、この手順で **3 テーマ・3 場面** を順に作って、**1 つの PR** にまとめて出します。持ち主は朝 8 時（日本時間）に PR を見ます。夜中に作るのは、朝に持ち主が AI を使うとき、使用量の 5 時間の枠がもどっているようにするため。手順を変えたいときは、このファイルを直します（次の日から反映される）。

## 持ち主が決めたこと

- 毎日 **3 つ**、新しいテーマで **1 テーマ 1 場面のページ** を作る（2026-11-27 に 1 つから 3 つへ。週の使用量を見て持ち主が数を変える）。気に入った物があれば、持ち主が別に頼む（ゲームにする、など）。
- **テーマは毎回考える**。持ち主の好みを中心にしつつ、**たまには持ち主がまだ好きと言っていない、まったく新しいアイデア** も出す。
- 1 日 1 つの PR に 3 場面をまとめる（番号や一覧がぶつからないように）。マージは持ち主がする。
- 3 つのうち **1 つは新しい方向**、2 つは好みの方向。

## 手順

1. **最新にする**: `git fetch origin && git checkout -B daily/<日付> origin/main`（日付は朝 8 時に見る日の、日本時間の YYYY-MM-DD）。まだマージされていない前の日の daily の PR があれば、その番号のぶん番号を空けて続ける（PR の差分の `game-looks-14/` のファイル名で分かる）。
2. **読む**: `CLAUDE.md`、`docs/taste.md`（全部）、`.claude/skills/look-retro-crt/SKILL.md`、この手順書、`docs/daily-log.md`（これまでのテーマ）。
3. **前の PR の感想を拾う**: `gh api -X GET search/issues -f q='repo:Yuki-Sakaguchi/game-looks is:pr label:daily' ` などで最近の日替わりの PR を探し、GitHub の MCP ツールで、持ち主（PR を作った bot 以外の人）のコメントとレビューを読む。感想があれば `docs/taste.md` の「毎日ひとつのテーマ」の節に、言われたことと結果だけを足す（推測は足さない）。`docs/daily-log.md` の その日の行の「感想」にも短く書く。
4. **3 つのテーマを先に決める**（下の「テーマの決め方」）。3 つどうしも、場所・時間・天気・色・題材がかぶらないように。
   以下の 5〜9 を **1 テーマずつ** くり返す（1 つ仕上げてから次へ。数より質）。1 つ終わるごとにコミットして push しておく（とちゅうで止まっても消えないように）。
5. **作る**: `game-looks-14/<番号>-<英語名>.html`。番号は `game-looks-14/index.html` の `LOOKS` の次（01, 02, …）。テイスト B（`retro.js` と第 8〜12 集の `pack-*.js`）で、見本と同じ作りの決まり（README の「作りの決まり」、スキルの点検表）に従う。人は `game-looks-13/pack-tale.js` の `TL.person`（4.5 頭身、服と帽子）を使ってよい（第 7〜12 集の `R.actor` でもよい）。必要ならテーマ用の部品を `game-looks-14/pack-<名前>.js` に作る（共通の部品集は変えない）。
6. **確かめる**: `node tools/cap.mjs check game-looks-14/<ファイル>` でエラー 0、`tools/out/` の絵を自分の目で見て、スキルの点検表で 2〜3 回直す。three.js の CDN に届かなければ先に `npm i --prefix tools three@0.160.0`。
7. **サムネイル**: `node tools/cap.mjs gif game-looks-14/<ファイル> game-looks-14/thumbs/<番号>.gif`
8. **一覧**: `game-looks-14/index.html` の `LOOKS` に 1 行。トップの `index.html` の第 14 集のカード（なければ、第 13 集〜第 12 集のカードと同じ形で 1 番上の集として足す）の数と、最新のサムネイル（新しい物が先頭、6 枚まで）。`README.md` の表の第 14 集の行（なければ足す）の数。
9. **記録**: `docs/daily-log.md` の表に 1 行（日付・番号・テーマ・方向（好み／新しい）・ひとこと）。
10. **PR**: 3 つできたら PR を 1 つ作る（GitHub の MCP ツール）。コミットは日本語（1 行めに何を足したか、本文にどう描いたか）。PR のタイトルは `毎日のテーマ <日付>: <テーマ1>・<テーマ2>・<テーマ3>`、ラベル `daily`（なければ作らずに省く）。本文は下の形を、テーマごとに 3 つならべる。
11. 失敗したとき（絵が良くならない、エラーが消えない、時間が足りない）も、できた所までで PR を出し、本文に何がうまくいかなかったかを正直に書く。3 つそろわなくてもよい。確かめていないことを確かめたと書かない。

## テーマの決め方

- `docs/daily-log.md` のこれまでのテーマと、場所・時間・天気・色・題材がかぶらないようにする（直近 7 日とは特に）。
- **好みの方向**（毎日 2 つ）: `docs/taste.md` の当たり（歩いてみたくなる 3D の世界、ゲームらしいカメラ、光と天気の空気感、生きている場面、大きい物・遠くの物の壮大さ、ファンタジー・廃墟・海・下町・蒸気・ダーク など）から、まだやっていない組み合わせ。
- **新しい方向**（毎日 1 つ）: 持ち主がまだ好きと言っていない題材や雰囲気に挑戦する（例: とても静かで何も起きない場面、極端な色、ふしぎな建築、水中や宇宙以外の異世界、ちがう文化の暮らし、季節の行事、乗りものの中 など）。ただし **外れた例**（`docs/taste.md`）は避ける: 箱の組み合わせの人・家・木、ざらざらのノイズを全面に、主役が小さい、画面加工のくせを強くしすぎる、机の上の見立て。
- テイストは B（描きこんだテクスチャとブラウン管）を基本にする。
- 既存のゲームや作品の名前・キャラクター・画面は写さない。商品名も書かない。

## PR の本文の形

```
## テーマ 1: <名前>（番号 NN）
（1〜2 行。どんな場所・時間・雰囲気か）

方向: 好みの方向 ／ 新しい方向（なぜ選んだか 1 行）

## 見どころ
- （止め絵で伝えたいこと、動いている物、大きい物・遠くの物 など 3〜5 行）

## どう描いたか
- （テクスチャ・光・カメラ・使った部品・足した部品）

## 確かめたこと
- cap.mjs check: エラー 0（横長・たて長）。絵を見て直したこと
- 確かめていないこと（実機の速さ など）

## 気になっている所
- 

開く: game-looks-14/<ファイル>.html

（テーマ 2・3 も同じ形でならべる。最後に「前の PR の感想を taste.md に写したか」を 1 行）

![サムネイル](https://github.com/Yuki-Sakaguchi/game-looks/blob/<ブランチ>/game-looks-14/thumbs/<番号>.gif?raw=true)
```
